PRODUCT FIELD NOTES · ARZ AI

把現場經驗，做成下一個 SaaS 模組。

真實流程有很多細節。ARZ AI 先解決實際問題，再整理成不同企業可重複使用的產品能力。以下案例來自團隊專案實作；客戶身分與營運數據不公開。

FIELD NOTE 01 · LINE Booking / 場地預約

運動場地 LINE 預約

既有電話、現場與老系統管理的預約如何接上 LINE？

現場課題

運動場館有不同場地、營業時間、休館與預約緩衝規則。新增 LINE 入口後，必須兼顧既有人工預約、多人同時搶位與後台審核。

流程怎麼被系統接起來

01

顧客入口

從 LINE 選場地、日期與開放時段，降低客服逐筆回答的需求。

02

可用時段計算

依使用時長、緩衝、週營業模板及臨時休館規則產生時段。

03

衝突保護

在預約建立時重新檢查占用，避免兩人同時預約相同時段。

04

後台與舊系統

管理員可核准或拒絕，再以匯出資料協助原有系統流程銜接。

可複用產品模組

場地資源模型 / 時段引擎 / 衝突檢查 / 審核狀態 / 舊系統匯出

實作進度／可查核界線

已有 LINE 預約、時段計算、衝突防護及後台程式模組與部署記錄；正式 D1 遷移狀態及 LINE 真機驗收仍須確認。

對 SaaS 的啟發

此專案萃取出的排程、資源與審核能力，可以延伸到會議室、教室、老師和其他預約業務。

FIELD NOTE 02 · LINE LIFF / 活動報名與文件

宮廟線上補財庫

紙本報名、付款紀錄與疏文資料如何走完同一條流程？

現場課題

法會報名包含信眾及親屬資料、活動選項、付款與疏文。若每一段都靠人工抄錄、核對，現場人員容易重複處理相同資料。

流程怎麼被系統接起來

01

LINE LIFF 報名

從 LINE 圖文選單進入線上表單，蒐集報名者與親屬資料。

02

場次與訂單

後台管理活動日期、名額、報名方案與訂單狀態。

03

金流與物流

專案設計含刷卡付款狀態銜接、結緣品與配送管理。

04

清冊與疏文

以報名資料產生 Excel 清冊與批次 PDF 疏文，支援調整文件版型。

可複用產品模組

活動模板 / 表單欄位 / 計價規則 / 金流訂單 / PDF 文件映射

實作進度／可查核界線

專案文件記錄 LIFF、活動管理、訂單、批次 PDF 等功能；實際商戶金流與正式營運成果須依個別環境驗收。

對 SaaS 的啟發

不同宮廟的活動、表單與疏文規則若能以設定取代每案改程式，將形成可重複導入的產業 SaaS。

PROJECT → PLATFORM

我們產品化的是可重複交付的工作流程。

兩個產業看起來不同，底層都有相同的流程：接受需求 → 驗證規則 → 更新狀態 → 交給人員處理 → 與原有工具交換資料。ARZ AI 正把這些共通能力整理為可設定的模組。

已具專案實作

預約資源、營業規則、衝突檢查、訂單管理、文件輸出等能力有對應的專案。

產品化中

整合跨企業帳號、可套用的產業模板、各企業獨立資料及管理權限。

探索中

以 Claude API 協助理解自然語言需求、整理資料與回覆草稿；重要操作仍走既有業務規則。

2026 / EARLY STAGE

從個案經驗，走向可設定、可訂閱的產品。

目前以台灣中小企業的人力與行政協調需求為起點，先用具體情境驗證功能，再把反覆出現的需求做成標準模組。訂閱式 SaaS 與導入整合是規劃中的商業模式；本站不使用未經核實的客戶數、營收或節省工時百分比。
